Publishing an MQTT topic to Home Assistant from Atari BASIC via FujiNet

You can do quite a lot with FujiNet, and the N: device offers many of the possibilities.

I needed a little distraction, so I wanted to be able to set an MQTT topic from the Atari.

The N: device (https://fujinetwifi.github.io/fujinet-docs/features/network-device/) supports many protocols, among them HTTP, HTTPS, FTP, SSH, … and TCP.

If you ask Gemini, it claims that the N: device includes an MQTT protocol, which is simply not true. Gemini and I then settled on TCP and "recreated" MQTT on top of it a bit.

The test environment is a running Home Assistant (HAOS) with a Mosquitto broker running as an "app" (formerly add-on). It's also useful to have MQTT Explorer running, either as an app in Home Assistant or somewhere else on the network.

The basic principle is fairly simple:

Put the IP address of the Mosquitto broker into line 10.

The login "testuser" with the password "atari" is encoded as decimal byte values. Create this user either in Home Assistant or in the Mosquitto app. Alternatively, an existing user can be encoded into the BASIC listing instead (the length bytes then have to be adjusted as well, see below). After creating the user, check with MQTT Explorer that it can log in.

Step 1: connecting (MQTT CONNECT)

Lines 140 to 149 send the following individual bytes. All values are decimal. Length fields in MQTT are two bytes (high byte, low byte).

PositionValue (dec.)Meaning
116Packet type CONNECT: the client wants to connect
229Remaining length: exactly 29 more bytes follow
3–40, 4Length of the protocol name: 4 bytes follow
5–877, 81, 84, 84"MQTT"
94MQTT protocol level (4 = version 3.1.1)
10194Connect flags (binary 11000010): username and password follow, clean session
11–120, 60Keep-alive: keep the connection open for 60 seconds

15–160, 8The username is 8 bytes long
17–24116, 101, 115, 116, 117, 115, 101, 114"testuser"
25–260, 5The password is 5 bytes long
27–3197, 116, 97, 114, 105"atari"

Using a different user: besides the letters, change the two length fields (positions 15–16 and 25–26) and the remaining length in position 2. It is always 10 + 2 + 2 + username length + 2 + password length; for testuser/atari: 10 + 2 + 2 + 8 + 2 + 5 = 29.

Step 2: publishing the topic (MQTT PUBLISH)

I'd like to set the topic AtariXL on the broker. Later, this topic can be defined as a sensor in Home Assistant's configuration.yaml and used in automations, e.g. to switch some lamp on or off.

For this, the RETURN key works as a toggle switch: each press switches the value between "ON" and "OFF".

Of course you could also read the fire button of a joystick instead…

The payloads are in lines 190–193 and 220–223. Both are sent with the RETAIN flag set, so the broker keeps the last value and Home Assistant sees the current state even if it connects later.

Topic "AtariXL" with payload "OFF" (lines 190 to 193)

Home Assistant

Home Assistant's configuration.yaml still needs to be extended:

mqtt:
  # ... your existing MQTT entries ...
  binary_sensor:
    - name: "Atari XL Button"
      state_topic: "AtariXL"
      payload_on: "ON"
      payload_off: "OFF"
      device_class: "power"

After restarting Home Assistant Core, the new sensor is available and can be used in automations.

Notes and outlook

The Atari FujiNet approach can also serve as a template for other devices. I can well imagine that it would also work with the Schneider CPC and the M4; maybe I'll try that in the next few days. For the C64, Meatloaf is also a good option.

In principle, it works with anything that can send individual bytes over TCP.

Everything can still be improved. For example, the Atari doesn't yet notice the acknowledgement (CONNACK) that Mosquitto sends back, and it closes the connection without an MQTT DISCONNECT, which the broker tolerates. I built it on a notebook with a HAOS VM, the Atari XL emulator Altirra (https://virtualdub.org/altirra.html) and a FujiNet emulator in the form of a matching bridge from the FujiNet project (https://github.com/FujiNetWIFI/fujinet-emulator-bridge). The real test was done with an unmodified Atari XL + FujiNet. Our Home Assistant has been running since 2021…

What can you do with it now? Good question… Build an 8-bit control panel for Home Assistant for the retro computer room? A back channel would be nice too, to show the status on the Atari XL.
